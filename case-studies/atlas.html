The work

I migrated the accreditation-readiness platform from DigitalOcean to AWS and built Laravel and FastAPI services for role-based access, auditable evidence review, and document indexing.

Atlas supports self-survey, gap analysis, and centralized accreditation document management. Access and review history are part of how evidence remains useful to its reviewers.

The documented AWS release path

  1. Build an immutable application image

    A manually dispatched GitHub Actions workflow builds the Laravel application and pushes a commit-tagged image to Amazon ECR.

  2. Release through SSM to EC2

    The host pulls the image by digest, saves the previous image reference, and recreates the Laravel web, scheduler, and worker services while preserving the edge and NLP services.

  3. Check application and dependencies

    The release checks Laravel's health route, database boot, and the NLP health command.

  4. Roll back explicitly

    A separate manual rollback selects a prior commit-tagged image and recreates the Laravel services without rerunning migrations. Schema changes need to remain compatible with the prior image during the release window.

Sanitized summary of the project's AWS CI/CD runbook. This describes the documented release boundary; it is not a live deployment verification or an execution log.

Keep the release boundary clear

The application image does not package the document corpus or rebuild the NLP service. Those runtime inputs remain separate, and a corpus or NLP change needs its own versioned release procedure.

Evidence and access

The project repository and institution-specific records are private. This walkthrough shares the application responsibilities and documented deployment process without exposing accounts, evidence documents, or infrastructure identifiers.
